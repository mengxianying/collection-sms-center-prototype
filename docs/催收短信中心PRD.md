# 产品需求文档：租后催收短信发送看板

**状态**：评审中　**最后更新**：2026-09-01　**版本**：V5.7
**干系人**：租后产品、催收运营、租后研发、测试、风控/合规、短信通道团队

---

## 一、发布摘要

本期仅建设“短信发送看板”，用于集中监控案件列表、买断催收及系统自动发送实际产生的短信批次和逐条发送结果。系统不新增发送入口，也不建设短信模板配置、模板拉取或绑定管理能力。

## 二、目标

- 让催收人员能够查询自己发送的短信批次及其发送结果。
- 让管理角色能够查看全量批次，并按操作员定位发送情况。
- 让业务可追溯频控拦截、失败原因和失败重发结果。
- 让案件详情展示客户当日短信与成功外呼次数，支持催收人员了解当日触达情况。
- 让客户回复与原催收短信、订单和发送批次形成可追溯闭环。

### 2.1 问题陈述

案件列表、买断催收及系统自动任务均可发起催收短信，但此前缺少统一的批次看板、逐条回执明细与客户回复记录：操作员无法快速追踪本人发送结果，管理角色无法按操作员核查全量数据，系统自动发送也无法按实际模板追溯，案件详情也无法直观看到客户当日触达情况。

同时，催收短信属于高时效业务。普通营销、通知或运营批量任务的积压、重试和降速不得影响催收短信进入通道的时效；失败、回执未返回和短信中心返回的频控拦截也必须有清晰、可审计的业务口径。

### 2.2 成功指标

| 目标 | 验证指标 |
| --- | --- |
| 建立发送批次闭环 | 人工发送提交后及自动任务实际发送后，100% 自动生成可按权限查询的批次记录；自动任务无命中订单时不生成空批次。 |
| 支持结果追溯 | 每个批次均可查看逐条结果、原始短信中心状态、失败/频控原因与触达时间。 |
| 满足权限隔离 | 操作员仅可见本人批次、明细及关联回复；管理角色可按操作员筛选全量人工及系统自动数据。 |
| 保障发送时效 | 普通短信任务积压或降速时，催收高优先级通道的消费不受影响，并可监控队列深度、等待时长和回执时延。 |
| 提升回复跟进效率 | 已关联催收发送记录的客户回复可按当天、手机号和客户姓名查询。 |

## 三、不做的事

- 不建设“短信模板配置”页面。
- 不对接基建中心拉取短信模板，不提供模板新增、绑定、编辑或删除能力。
- 不改变案件列表、买断催收既有的短信选择和发送流程。
- 不在看板新增“新建发送批次”或批量上传发送入口。

## 四、用户与权限

| 角色 | 可见范围 | 可执行操作 |
| --- | --- | --- |
| 操作员 | 仅本人创建的批次及其发送明细 | 查询、查看明细 |
| 管理角色（催收工作台） | 全部内部操作员及系统自动的批次、发送明细及关联回复 | 查询、按操作员筛选、查看明细 |
| 内部操作员（我的工作台） | 仅本人归属的批次、发送明细及关联回复 | 查询、查看明细 |

## 五、功能需求

### 5.0 案件详情当日触达统计

- 展示位置：`案件详情 → 作业详情 → 客户信息 → 基本信息`下方新增“风险与触达”信息列表；沿用详情页现有表格样式，不在基本信息右侧展示独立卡片。
- 出域投诉、投诉预警、售后工单的数量均不统计状态为“已取消”的工单；其余状态按实际关联记录计数。
- 统计口径为客户维度、自然日累计：同一客户的多个手机号合并计算。
- 今日短信用于展示客户当天短信触达情况，不参与催收系统的短信条数限制；今日外呼用于催收人员掌握当日已触达次数。
- 客户手机号默认脱敏；案件详情页提供“小眼睛”按钮，仅具备敏感信息权限的用户可查看完整手机号，离开或切换工作台后恢复脱敏状态。
- 案件详情沿用现有“作业详情”结构展示：客户信息、基本信息、风险与触达、收货地址、催记备注记录和客户回复按区块排列；风险与触达位于基本信息下方，以一行列表展示出域投诉、投诉预警、售后工单、今日短信和今日成功外呼。

### 5.0.1 成功外呼次数配置

- 外呼计数范围：仅统计催收系统内由催收人员发起且外呼成功的记录；外呼记录以催收系统内的外呼结果为准，其他业务系统或非催收场景的通话不计入。
- 外呼前置条件：仅当案件归属有效、号码有效、处于允许外呼时段、未命中黑名单或禁呼规则，且客户当日外呼次数未达上限时，才允许发起外呼。
- 外呼计数时点：外呼通道受理并发起拨号成功、返回“外呼成功”结果后计 1 次；未接通、拒接或很快挂断但已成功外呼出去的，均计 1 次。仅点击按钮、外呼通道受理前失败或未成功外呼则不计数；操作员手动再次拨打计为新的一次，通道内部自动重试不重复计数。
- 外呼拦截交互：催收人员点击发起外呼时，系统先校验当日成功外呼次数和临时预占量。若已达到配置上限，则不调用外呼通道，并弹出提示：`今日用户已经外呼已经达到X次，无法再次外呼`；其中 `X` 为该客户当日已成功外呼次数。未达上限时允许发起，待收到外呼成功结果后再写入当日成功次数。
- 配置规则：外呼次数阈值可设置为正整数，默认 3；调整后仅影响后续发起校验，不追溯修改当日已累计次数。配置变更需记录操作人、变更前后值和生效时间。
- 展示与追溯：案件详情展示客户当日短信触达数量及成功外呼累计次数。短信条数限制与频控判定由短信中心统一执行，催收系统不做短信额度、预占或本地频控拦截。

### 5.1 批次生成

- 案件列表、买断催收及案件详情页手工短信发送等既有人工发送操作完成后自动生成短信批次。
- 案件详情页中，操作员手工点击“短信发送”并确认后，按“订单 + 实际选择的短信模板 + 发送时间”创建 1 条独立批次；批次来源记录为“案件详情页手工短信发送”，操作员为当前登录操作员。每个订单的每次手工发送动作独立归批，不与同一案件下其他订单、其他模板或其他发送动作合并。
- 案件详情发送前校验案件归属、黑名单/禁发和通道可用性；短信条数限制与频控判定由短信中心统一执行。短信中心返回频控拦截时，更新对应批次明细并展示返回原因。
- 系统自动发送也必须产生批次记录。自动任务每次实际执行时，按“自动任务 + 实际命中的短信模板 + 执行时间”生成批次；同一次自动任务命中多个模板时，每个实际模板分别生成独立批次；无符合发送条件的订单时不生成空批次。
- 现有自动任务示例包括：T-5 首期/2期账单提醒（每日 09:30）、T-3 账单即将到期（每日 09:30）、T-1 账单即将到期（每日 09:30）、T0 账单到期提醒（每日 08:00）、T-20 买断提醒（每日 10:30）、T0 队列晚班还款提醒（每日 21:00）。本期不改动上述任务配置或调度，仅将实际发送结果归入看板。
- 自动批次的操作员固定展示“系统自动”，发送方式可记录为“系统自动”；批次列表不新增“任务名称”列，自动任务名称仅作为后台审计维度。
- 自动发送与人工发送共用催收高优先级通道、客户日频控、状态回执、发送明细和失败重发审计口径。
- 批次记录消息类型、发送方式、操作员、创建时间及汇总结果。
- 看板仅查询和监控，不提供新建批次入口。

### 5.2 发送批次列表

- 菜单入口：`催收工作台 → 短信发送看板`。
- 默认查询当天 `00:00:00–23:59:59`；点击重置后恢复当天范围。
- 筛选条件：创建时间、操作员、发送状态。
- 催收工作台的管理角色可选择任意内部操作员或“系统自动”查询；我的工作台的操作员筛选默认选中当前登录操作员且不可变更，仅查询分配给当前操作员的发送批次，不展示系统自动批次。服务端必须按批次创建人再次校验，不能仅依赖前端限制。
- 列表字段：批次 ID、消息类型、短信内容、发送状态、总条数、成功、失败、频控拦截、状态待返回、发送开始时间、操作员和操作；不展示发送方式与任务名称。
- 消息类型统一枚举为：当天提醒、1-7队列、8-30队列、买断提醒、买断逾期。展示格式为“租赁/分期（业务阶段）”。账单催收可选“当天提醒、1-7队列、8-30队列”；买断催收可选“买断提醒、买断逾期”，且仅租赁业务展示买断催收。分期不展示买断类型。选择产品、发送类型、消息类型后，只展示该业务阶段已绑定且可用的短信模板，例如“租赁（当天提醒）”“分期（1-7队列）”“租赁（买断逾期）”。
- 默认展示符合权限范围与当天时间范围的批次数据；批次列表按 10 条/页分页。
- 列表上方展示当前筛选结果的合计：批次数量、总条数、成功、失败、频控拦截、状态待返回；合计基于全部符合筛选条件的数据计算，不受分页影响。
- 发送状态口径：该批次已进入短信中心的明细未全部返回终态时为“发送中”；全部有了终态结果即为“已完成”，不以全部成功为完成条件。短信中心终态包括已送达、发送三方失败、未送达及频控拦截；频控拦截不作为等待终态的条件。
- 计数口径：总条数为实际进入短信中心处理的明细数，成功、失败和状态待返回之和应与总条数一致；频控拦截单独统计，不计入总条数。
- 批次 ID 为可点击链接，点击后进入该批次的“发送情况明细”独立页面。
- 不展示任何计费相关字段。

### 5.2.1 短信中心状态映射

发送明细以短信中心回传状态为准，租后系统不再将“发送成功/发送失败”作为笼统状态展示。

| 短信中心状态 | 租后系统展示/统计状态 | 业务含义与处理 |
| --- | --- | --- |
| 发送三方失败 | 失败 | 短信中心或其下游通道失败，属于未送达终态。 |
| 发送三方成功 | 状态待返回 | 短信中心已成功受理/提交下游通道，等待最终送达回执。 |
| 发送中 | 状态待返回 | 短信仍在短信中心处理或等待下游受理。 |
| 未送达 | 失败 | 已获得最终未送达结果，例如号码停机、运营商拒绝。 |
| 已送达 | 成功 | 已获得成功送达回执。 |
| 频控拦截 | 频控拦截 | 短信中心根据其统一频控规则返回的终态结果；催收系统仅展示并记录返回原因。 |

- “状态待返回”统计“发送三方成功”和“发送中”两类尚未得到最终送达结果的记录。
- 发送明细和筛选项只展示租后业务状态“成功、失败、频控拦截、状态待返回”；每条明细同步展示原始短信中心状态，供审计追溯。
- 频控拦截由短信中心统一执行并返回；催收系统不做短信条数限制或本地频控拦截，明细展示短信中心返回的频控原因。
- “失败”汇总指标统计“发送三方失败”和“未送达”；发送明细必须保留短信中心回传原因，便于追溯。

### 5.3 发送情况明细

- 每个批次提供“查看明细”操作；点击批次 ID 或“查看明细”均进入对应批次的独立明细页面。
- 明细页面展示批次 ID、消息类型、总条数、成功、失败、频控拦截、状态待返回等概要信息，并提供返回短信发送看板入口。
- 明细字段：手机号（默认脱敏）、客户姓名、订单号、消息内容、发送结果、失败/拦截原因、发送时间、触达时间；订单号按纯数字订单号展示。
- “消息内容”使用实际发送时的变量值填充短信模板，例如将 `{订单号}`、`{应还金额}`、`{买断金额}` 替换为本条订单的真实参数；列表单元格超出宽度时省略展示，鼠标悬浮自动展示完整发送内容。
- 触达时间仅在短信通道确认客户成功触达时展示；发送失败、频控拦截及等待回执的记录展示“—”。
- 明细页筛选条件：发送结果、手机号、客户姓名；手机号、客户姓名采用精确匹配。
- 页面提供全局“小眼睛”控制：仅具备敏感信息权限的用户可点击查看完整手机号；默认展示脱敏手机号，切换状态仅影响当前页面展示。
- 租后系统发送结果只包含：成功、失败、频控拦截、状态待返回；原始短信中心状态作为明细辅助信息展示，不作为租后业务筛选项。
- 频控拦截必须展示短信中心返回的明确原因。
- 明细列表支持按发送结果、手机号或客户姓名查询，并按 10 条/页分页。

### 5.4 失败重发（后台能力）

- 短信发送看板不提供“失败重发”操作按钮；如确需重发，由后台受控流程执行并保留审计记录。
- 仅允许对已完成批次中的终态失败明细发起重发；成功、状态待返回和频控拦截记录不得随失败重发再次发送。
- 重发沿用原短信内容及业务变量，但必须重新执行案件归属、黑名单/禁发规则和短信通道可用性校验；短信条数限制与频控判定仍由短信中心统一执行，并回传本次重发的频控结果。
- 原失败记录、失败原因、重发操作人、重发时间和重发结果必须保留，便于审计；重发后的明细结果独立记录，不覆盖原始失败结果。
- 重发提交后，待获取终态回执的明细计入状态待返回；只有该次重发进入短信中心的明细全部有了终态结果，重发批次才展示为已完成。

### 5.5 短信回复记录

- 菜单入口：`催收工作台 → 短信回复记录`，作为独立页面展示客户对已发送催收短信的回复。
- 仅纳入可关联至催收发送记录的客户回复；无法匹配客户、订单或发送批次的上行短信进入异常队列，由运营另行处理，不进入本列表。
- 列表字段：回复时间、手机号、客户姓名、回复内容；默认按回复时间倒序排列。不展示订单号与发送内容；关联订单和原短信仅用于系统内部关联、权限过滤和审计追溯。客户姓名展示全名，不做截断或脱敏。
- 手机号默认脱敏展示；页面提供全局“小眼睛”控制，仅具备敏感信息权限的用户可切换查看当前列表中的完整手机号。回复内容仅用于催收跟进与审计，不得用于营销触达。
- 默认查询当天 `00:00:00–23:59:59` 的回复记录；点击重置后恢复当天范围。筛选条件：回复时间范围、操作员、手机号、客户姓名；筛选项可组合使用。手机号、客户姓名采用精确匹配；不提供回复内容查询条件。
- 数据范围与操作员筛选：催收工作台的管理角色可查看全部内部操作员及系统自动发送批次关联的短信回复，并可按操作员筛选；我的工作台仅展示当前操作员所创建发送批次关联的短信回复，操作员筛选默认选中本人且不可变更。服务端必须基于关联批次的创建人执行数据权限校验。
- 列表按 10 条/页分页。原发送批次可通过后台审计记录追溯，不在此列表提供跳转入口。

### 5.6 高优先发送与性能保障

- 案件列表、买断催收等既有入口提交的催收短信，必须进入独立的催收高优先级发送通道。
- 催收短信不得与营销、通知、运营批量等普通短信任务共用会导致等待或降速的消费队列；普通队列积压、失败重试、批量任务和其他业务限流不得影响催收短信的入通道时效和发送速率。
- 业务校验通过后，系统不得对催收短信进行人为排队、合并等待或延迟发送，应立即路由至高优先级通道处理。
- 为催收短信配置独立高优先级队列、消费者/工作线程和保障并发，不与普通短信任务抢占消费资源；普通任务发生积压、扩容、重试或降速时，催收高优先级队列仍须保持正常消费。
- 高优先级队列出现待处理任务、持续堆积、消费异常或通道提交异常时，必须触发监控告警。监控指标至少包括队列深度、等待时长、消费速率、通道提交成功率和回执时延。
- 短信通道自身限流、故障或回执延迟时，系统应如实记录通道状态与原因，不得以“高优先级”掩盖通道异常；容量、并发与告警阈值由短信通道团队和租后研发在开发前通过压测确认。

### 5.7 菜单入口与数据范围

- 在`催收工作台`、`我的工作台`下分别增加“短信发送看板”“短信回复记录”两个菜单。
- 催收工作台的两个菜单供管理角色使用，可查看全部内部操作员及系统自动归属的数据，并可按操作员筛选。
- 我的工作台的两个菜单供内部操作员使用，只展示当前登录内部操作员创建的批次、发送明细及其关联短信回复；操作员筛选默认选中本人且不可变更，不展示系统自动数据。
- 两处菜单使用同一套页面能力，但服务端必须根据当前入口、登录身份、组织归属和数据归属执行行级权限校验，前端菜单及筛选限制不可替代服务端鉴权。

## 六、验收标准

- [ ] 发送看板默认展示当天的批次，且用户跨日打开页面时默认日期随当天变化。
- [ ] 批次中存在未返回终态的已提交明细时展示“发送中”；全部有了终态结果即展示“已完成”，频控拦截不作为等待终态的条件。
- [ ] 短信发送看板不展示“失败重发”操作按钮；后台重发如发生，必须重新执行案件归属、黑名单/禁发与通道校验，并保留原失败及重发审计记录；短信中心负责本次重发的频控判定。
- [ ] 操作员无法通过筛选参数或接口获取其他操作员创建的批次和明细。
- [ ] 管理角色可按操作员筛选全量人工及系统自动批次。
- [ ] 每个批次可打开“发送情况明细”，并查看发送结果及失败/拦截原因。
- [ ] 点击批次 ID 可进入对应批次的独立明细页面；批次列表与明细列表均支持分页。
- [ ] 列表展示“频控拦截条数”，与明细中的频控拦截记录可追溯对应。
- [ ] 外呼次数以催收系统外呼记录为准；客户已达上限时，外呼入口不调用通道并弹出“今日用户已经外呼已经达到X次，无法再次外呼”。
- [ ] 外呼通道受理并发起拨号成功、返回外呼成功结果后计 1 次；未接通、拒接或很快挂断但已成功外呼出去仍计数；仅点击按钮、外呼通道受理前失败或未成功外呼不计数。
- [ ] 外呼前必须校验案件归属、号码有效、允许外呼时段、黑名单/禁呼规则和当日外呼余量。
- [ ] 我的工作台下的短信发送看板仅返回当前操作员创建的批次；操作员筛选默认选中本人且不可编辑，不展示系统自动批次。
- [ ] 发送看板按当前筛选结果展示批次数量、总条数、成功、失败、频控拦截、状态待返回六项合计，且合计不受分页影响。
- [ ] 短信回复记录可展示已关联催收发送记录的客户回复，并支持回复时间、操作员、手机号和客户姓名筛选；不提供回复内容查询条件。
- [ ] 短信回复记录默认展示当天数据，点击重置后恢复当天 `00:00:00–23:59:59` 范围。
- [ ] 催收工作台可查看全部发送批次关联的短信回复并按操作员筛选；我的工作台仅可查看本人发送批次关联的回复，操作员筛选固定为本人。
- [ ] 短信回复记录按回复时间倒序、10 条/页展示；列表不展示订单号、发送内容和关联批次 ID，客户姓名展示全名。
- [ ] 催收短信与普通短信任务使用隔离的高优先级发送资源；普通任务积压或降速时，催收发送不受影响。
- [ ] 催收短信业务校验通过后立即进入高优先级通道，不存在人为等待、合并等待或普通任务排队导致的内部延迟。
- [ ] 系统可监控并告警催收队列深度、等待时长、消费速率、通道提交成功率和回执时延；通道异常能追溯至队列、通道或批次。
- [ ] 催收工作台、我的工作台下均可进入短信发送看板和短信回复记录，且两处数据范围分别符合全量管理、内部本人规则。
- [ ] 看板不出现短信模板配置、基建中心模板拉取、模板绑定或新建发送批次入口。
- [ ] 自动任务实际发送后，按自动任务、实际短信模板和执行时间生成可追溯批次；同一任务命中多个模板时分别归批，无命中订单不生成空批次。
- [ ] 自动批次操作员展示“系统自动”，催收工作台管理角色可筛选和查看；我的工作台不得返回系统自动批次及关联明细、回复。
- [ ] 案件详情页手工点击“短信发送”并确认后，按订单和实际选择模板自动创建独立批次；批次来源为“案件详情页手工短信发送”，批次操作员为当前登录操作员，详情发送不得与其他订单或模板混合归批。
- [ ] 案件详情发送仅校验案件归属、黑名单/禁发和通道可用性；短信条数限制与频控判定由短信中心统一执行，催收系统展示其返回的频控结果与原因。
- [ ] 案件详情的基本信息下方展示“风险与触达”信息列表，使用详情页现有表格样式展示出域投诉、投诉预警、售后工单、今日短信及今日成功外呼；前三类数量均排除状态为“已取消”的工单，不展示右侧独立卡片。
